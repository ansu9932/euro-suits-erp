# Multiple reporting managers

In Access & new users → Add user / Edit access, open Reports to and check one or more managers. Clear all checks for no manager. The compact native disclosure supports keyboard navigation and ordinary checkboxes without Ctrl/Cmd selection. Saved names appear in the Users register. The organisation tree shows an employee under each manager; a shared descendant subtree expands once to avoid exponential duplication, and search retains every matching ancestor branch.

Existing single reporting lines are backfilled by additive backend migration 27 into user_reporting_managers. The API accepts reports_to_ids and retains reports_to_id as a compatibility mirror. Older clients that echo their unchanged scalar preserve all links; changing that scalar on an account with multiple managers returns 409 rather than dropping assignments. Explicit empty arrays clear reporting assignments.

Super Admin account controls, developer/self-account restrictions, optimistic versions, the shared user-write advisory lock, protected deletion and audit history remain. Backend validation rejects invalid/inactive/developer/self managers and cycles through any upstream manager. Disabling/deleting a manager remains blocked while active direct reports reference them, including secondary links. Employee replacement copies all upstream managers and transfers only the replaced manager's incoming links, retaining other managers. Reporting never adds company/team/buyer/line/feature visibility.
